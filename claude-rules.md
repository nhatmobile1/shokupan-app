# Claude Development Rules

## Workflow Process

### 1. Planning Phase
- **Think through the problem** thoroughly before starting
- **Read the codebase** to identify all relevant files
- **Write a plan** to `tasks/todo.md` with clear, actionable items

### 2. Task List Structure
- Create a **checklist of todo items** that can be marked complete
- Break down work into discrete, manageable tasks
- Each task should be clear and specific

### 3. Plan Verification
- **Check in before beginning work**
- Wait for plan approval before proceeding
- Ensure alignment on approach and scope

### 4. Execution Phase
- Work through todo items **one at a time**
- **Mark items as complete** as you finish them
- Track progress systematically

### 5. Communication Standard
- Provide **high-level explanations** for each change
- Keep updates concise and focused
- Explain the "what" and "why" of changes

### 6. Simplicity Principle
- Make **every task as simple as possible**
- Minimize complexity at all costs
- **Impact as little code as possible**
- Avoid massive or complex changes
- Every change should touch only necessary code

### 7. Review and Documentation
- Add a **review section** to `tasks/todo.md` when complete
- Include a summary of all changes made
- Document any relevant information or considerations

## Core Principles

### 🚫 NEVER BE LAZY
- **Find the root cause** of every bug
- **No temporary fixes or workarounds**
- Act as a **senior developer** would
- Take ownership and solve problems properly

### ✨ PRIORITIZE SIMPLICITY
- Make fixes and changes **as simple as humanly possible**
- **Only impact necessary code** relevant to the task
- Touch **nothing else** beyond what's required
- **Minimize code impact** to reduce bug risk
- **Simplicity prevents bugs** and makes code maintainable

## Key Mantras

> "Simple changes, minimal impact, zero laziness"

> "Every line of code changed is a potential bug - change only what's necessary"

> "Senior developers fix root causes, not symptoms"
